# Report 11: the joint round (v16) partition audit (2026-09-18)

Follow-up to the ten-agent review, run before the v16 launch. Every count is regenerated by
`experiments/019-simb-multimodal/scripts/split_gene_overlap_audit.py`

## Q1. Split-drawing rule: by record index, where one record is one deletion gene set

`GenotypeAggregator.aggregate_check` (`torchcell/data/genotype_aggregate.py:34-70`) keys a
record by the sorted SET of systematic gene names (perturbation type dropped). Measured:
fig3_proteome has 4,681 records and 0 pairs sharing a gene set; fig3_core 5,125 records, 0
pairs. Messner replicate strains are already merged (140 records named
`ProteomeMessner2023Dataset+ProteomeMessner2023Dataset`, 4 triple), and a Kemmeren and a
Messner strain of one gene are one record (the 1,349 "both"). Exact-genotype duplicates
cannot cross the split; they do not exist as separate records.

The draw (`torchcell/datamodules/cell.py:384-488`, called from `train_cgt_multitask.py:2617-2634`
with `split_indices=["phenotype_label_index", "perturbation_count_index"]` and
`random_seed=split_seed`): `random.seed(seed)`, then for each index key the record indices
are shuffled and cut 80/10/10; the per-key assignments are intersected, and records assigned
to two splits under different keys are re-placed to keep the ratio. The result is cached as
`data_module_cache/index_seed_<k>.json`. Nothing looks at gene identity: a Sameith double and
the singles of its two genes are three records assigned independently. The only gene-aware
path (`pinned_test_indices`) is unused.

v13, v14 and v16 differ only in the store and the post-draw filter
(`train_cgt_multitask.py:2706-2725`): v13 = fig3_core + `require_modalities
[expression_log2_ratio]`; v14 = fig3_proteome + `[protein_abundance]`; v16 = fig3_proteome +
`[]`. Since the filter runs after the draw, v16's proteome rows are exactly v14's at every
seed (3,581 / 448 / 447).

## Q4. An expression-only reference arm on the v16 partition

Works by re-pointing the existing `per_gene` head; does not work with `per_gene_aux` alone
(`equivariant_cell_graph_transformer.py:2416-2418` raises `per_gene_aux requires the
per_gene head`). A genotype without expression is a row-mask-False row, not a NaN row
(`_extract_targets_and_masks`, `train_cgt_multitask.py:1018-1167`); `MaskedMultitaskLoss`
folds NaN into the feature mask and row-selects, returning a graph-connected zero for an
empty selection (`equivariant_cell_graph_transformer.py:1990-2040`, `distributional.py:983-994`);
the reveal schedule reveals nothing on unsupervised rows (`_masked_step`, 1234, 1271); the
metric skips heads with no supervised rows and routes NaN to the sparse Pearson (1472-1478,
296-330). Overrides, now the `J_expr_s<k>` arm of `gh_expr_008_arm.sh`:

```
multitask.active_heads=[per_gene]
multitask.head_phenotypes.per_gene=[expression_log2_ratio]
multitask.head_phenotype_names.per_gene=expression
multitask.standardize_per_feature_target=[per_gene]
trainer.checkpoint.monitor=val/expression/pearson_per_feature
trainer.checkpoint.metric_monitor=val/mean/pearson_per_feature
```

Byte-for-byte the v13 and v14 head, loss, reveal schedule `[0, 10, 100, 1000]` and z-score;
an epoch is 3,722 rows of which 1,244 are supervised.

Smoke tests (GilaHyper, CPU, `trainer.accelerator=cpu precision=32-true
+trainer.limit_train_batches=0.1 max_epochs=1`, the full 478-row validation with the reveal
sweep, offline W&B project `torchcell_019_smoke_audit`; the GPU cards were held by 028 jobs):

## Q5. Recommendation

Facts from the components of the "shares a deleted gene" relation over the 4,681 genotypes:
4,545 components; 18 multi-member (sizes 3 x 12, 5 x 2, 7, 9, 11, 81) holding 154 genotypes,
the 72 doubles plus the 82 singles of their genes (every double gene is also a single; 32
genes sit in 2 to 9 doubles); all 154 carry expression, none is proteome-only.

- Keep the current draw. The proteome contrast is paired with v14 on identical strains at
  every seed and is gene-disjoint for the proteome head. Any redraw breaks pairing with the
  16 finished v14 runs.
- Add `J_expr_s<k>` on the same `index_seed_<k>.json`, so J_ref, J_expr and J_joint differ
  only in the active heads; the expression head is scored on the same 155 / 155 expression
  genotypes in J_expr and J_joint. Comparability to v13 stays "same label, head and
  objective, different draw".
- Gene-disjoint metrics as an evaluation subset, not a new split: drop the shared rows (15
  to 22 per split, all expression-carrying) from the expression metric, leaving val 137 /
  138 / 136 / 135 and test 140 / 135 / 138 / 133 genotypes for seeds 0 to 3; the proteome
  metric is unchanged. Report both.
- A 025-style gene-set-identity split is not needed for the above. It is needed only if
  TRAIN itself must be gene-disjoint from val and test; that re-draws rows and breaks the
  v14 pairing, so it would be a new round. The 025 precedent
  (`experiments/025-solid-growth/scripts/make_010build_index_artifacts.py:88-150`) would move
  the 18 components (154 genotypes, 3.3%) as units and keep the 4,527 singletons' assignment;
  v14's proteome rows would change by at most the 70 "both" genotypes inside them.
- Hypothesis (untested): excluding the 154 shared genotypes from the expression metric moves
  the joint-minus-expression contrast by less than the 0.005 within-partition sd quoted in
  the v16 note.
