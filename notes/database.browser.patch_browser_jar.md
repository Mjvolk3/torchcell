## 2026.09.18 - Why the seed goes into the jar

Neo4j 5.26 serves its Browser from `lib/neo4j-browser-2026.06.30+0.jar` (818 entries,
static files under `browser/`), and there is no configurable static directory beside
it. The page comes with `Content-Security-Policy: script-src 'self' cdn.segment.com
canny.io`, so an inline `<script>` is blocked and the seed has to be a file served by
the same origin. The script adds `browser/torchcell-seed.js` to the jar and inserts
`<script src="./torchcell-seed.js"></script>` ahead of the page's
`<script type="module" ... src="./assets/index-*.js">` line, so the seed writes local
storage before the Browser's bundle rehydrates its persisted state. The page is served
`Cache-Control: no-store`, so a relaunched container shows the new page at once.

The jar is rewritten entry by entry through a temporary file beside it (compression
kept), and the run is idempotent: an already-tagged page is left alone and the seed
entry is replaced. Run by `database/docker/Dockerfile.tc-neo4j-browser` with the image's
own python (stdlib only). `tests/torchcell/database/test_patch_browser_jar.py` builds a
synthetic jar and checks the tag position, the second run, and the refusal of a page
without the module script line. The seed itself is generated by
[[torchcell.database.browser_style]].
