The TorchCell ontology is the schema of the typed experiment: the classes a
`genotype x environment -> phenotype` record is built from, and how they relate. The
same classes define what the knowledge graph stores, so the ontology is the shared
vocabulary of the library and the database.

It is not yet an ontology in the formal sense. In the BioCypher schema configuration
every class has exactly one parent. Nearly all attach directly to a Biolink class, the
phenotype classes all to `phenotypic feature` for example, and two attach to another
TorchCell class (`perturbation` and `segregant genotype` under `genotype`). That is a
tree one level deep under Biolink, so it is a directed acyclic graph only trivially: no
term has two parents, and there are no TorchCell terms between a class and its Biolink
parent. The explorer links every class to its Biolink counterpart. The intended shape is
a DAG with TorchCell's own intermediate terms, and more than one parent where a
measurement is of more than one kind, because that is what lets equivalent measurements
from different datasets be unified under one parent term and queried together.

The explorer connects the schema to the data stored in it. Each class lists the served
datasets whose records can hold it, and each dataset links to its page in the docs.
