It is live (`trainers/neo_regression.py`), so this is a bug, not a quirk. The implemented value is pinned, and `test_plackett_luce_value` asserts the paper's cumulative value (3.7208676519 on the fixture) as a strict xfail; fixing the loss flips both, which is the intended signal. The fix itself changes a live training loss and is left to its own PR.

A fix was written and reverted: its six `preprocess_raw` call sites run only under `--data`, so diff-cover scored the change 71% and would have blocked the PR.
