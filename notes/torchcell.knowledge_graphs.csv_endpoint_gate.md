## 2026.10.15 - The gate before `neo4j-admin import`

Stage 1 of the ontology unification, guard (c3) of [[scratch.2026.10.15.ontology-audit-C_serving]] section 4, made the mandatory check per [[scratch.2026.10.15.ontology-review-3-serving]] finding 8: every config under `biocypher/config/` sets `skip_bad_relationships: true`, so flipping it alone only moves a dangling-row failure into the import after the whole generation. The flag stays as it is; this module is the hard stop.

`python -m torchcell.knowledge_graphs.csv_endpoint_gate <biocypher-out dir> [--header-dir DIR] [--no-resolve-datasets] [--report PATH]` loads the `:ID` column of every node CSV into one id table (a 64-hex content id packed to its 32 bytes, any other id as its bytes), streams every edge CSV's `:START_ID` and `:END_ID` against it, and reports every endpoint with no node grouped by edge label and side. Where a gap exists it walks the known end of each dangling row along the `member of` ladder to a `Dataset` node, the ladder read off a 1000-row sample of each edge file (the yaml's edge names are not the file labels: `publication mentions experiment` is the `Mentions` file), so the report names the dataset whose records produced the row. Exit 1 on any gap. Rows are read as bytes and split on the tab: BioCypher writes no multiline field and a node id is the first field, which is what lets the 261 G `Experiment` file be read without parsing its blobs.

Wired into `database/slurm/scripts/gilahyper_live_rebuild-slurm_docker.slurm` inside the import branch, after the dev fence and before the build container starts, writing `<job>_csv_endpoint_gate.{txt,json}` beside the other job artifacts; a failure exits the job with "the fix is in the data, regenerate after it". The expected-counts block after the import stays as the live-store counterpart.

Measured on the job 4901 partial (`/db/database/biocypher-out/2026-10-14_03-53-33`, 383 G of CSV from 124 of 170 adapters, 47.3 M `PerturbationMemberOf` rows, read-only, headers borrowed through `--header-dir` because the killed generation never wrote them): 1281 s wall (21 min 21 s under `/usr/bin/time`, one process at `nice 19`, 30.6 G maximum resident set for 188.5 M node ids), over 188,497,777 node rows in 47 labels and 624,323,707 edge rows in 14 labels (47,251,386 `PerturbationMemberOf`, 95,916,158 `Experiment` nodes); the 261 G `Experiment` file alone took about 5 min at 0.8 GB/s. That partial dangles by construction (its `Dataset`, `Genome` and `Temperature` node files are empty, written only after the last adapter), so the measurement ran with `--no-resolve-datasets`; a production run resolves the few gaps it finds through two more edge-file passes.

Tests: `tests/torchcell/knowledge_graphs/test_csv_endpoint_gate.py` on a synthetic directory (the Carruthers shape resolved to its dataset through `GenotypeMemberOf -> ExperimentMemberOf`, an unresolvable dangling `Dataset` end, both sides dangling, borrowed headers, a non-first id column parsed as csv, a wrong field count refused, the CLI's exit code and JSON).

## 2026.10.15 - The gate checks the endpoint's label, not only its existence

**The blind spot.** The gate of this morning asked whether an endpoint id names SOME node. An id that was written under another label passes that check and `neo4j-admin import` imports the row onto that other node: that is how the whole-genotype interned constants, whose id was the bare sha256 of the same bytes the genotype node hashes, took the place of 218,258 genotype nodes on the job 4901 partial and 14,573 on the served KG 3.0 store ([[torchcell.datamodels.interned_constant]]). The existence check reported 4,233 dangling `PerturbationMemberOf` rows and said nothing about 2,900,104 rows that landed on an `InternedConstant`.

**What it checks now.** Every node row's `:LABEL` column (BioCypher's ancestry, `PerturbedSegregantGenotype|Genotype|...`, the labels Neo4j gives the node) is interned as one of about a hundred distinct strings, and the id table maps each packed id to that string's index. The schema yaml's `source` and `target` of every `represented_as: edge` class, PascalCased as BioCypher names the files, are the allowed labels per side, and an endpoint satisfies its side when ANY label of its ancestry is allowed: `target: genotype` is met by a perturbed segregant genotype exactly as `MATCH (g:Genotype)` matches that node in the store, so the yaml needs no edit and the check cannot drift from the store's own semantics. A `LabelGap` names the edge, the side, the leaf label found, the rows, the declared labels and the datasets (through the same ladder the dangling rows use). An edge file no class declares (`Mentions`, the Biolink predicate the adapter emits itself) is listed as undeclared and not label-checked. A node id written under two different ancestries is an `IdCollision`, with or without an edge on it, since the import keeps one row and never says which. `--schema` names the yaml; the default is the repository's next to the imported package. Any gap, label gap or collision fails the gate.

**Measured on the job 4901 partial** (`--header-dir`, resolution on, `experiments/database/results/csv_endpoint_gate_labels_4901.json`): the four label gaps are exactly the collision, `GenotypeMemberOf :START_ID` 1,948,098 rows, `PerturbationMemberOf :END_ID` 121,180, `SegregantBackgroundOf :START_ID` 709,716 and `SegregantBackgroundOf :END_ID` 121,110 rows on `InternedConstant` nodes; no id collision (the sink had already dropped the second row, which is what the sink now refuses, [[torchcell.fast_csv]]); `Mentions` undeclared; the 148,017,138 dangling rows of the partial's empty `Dataset` and `Publication` files unchanged. Cost: 1,473 s wall and 40.1 GB maximum RSS, against lane A's 1,281 s and 30.6 GB on the same partial with `--no-resolve-datasets`. The label check itself is one list index per endpoint and the ancestry table is about a hundred strings, so the two runs differ in settings more than in the check: with resolution on, the gate keeps one anchor id for every one of the partial's 148 M dangling rows, which a complete build does not have. Hypothesis, not profiled: those anchors are most of the 9.5 GB difference. Datasets stayed unresolved because the partial has no `Dataset` node rows.

**Tests.** `test_edge_declarations_are_pascal_cased_file_labels`, `test_a_clean_directory_passes_the_label_check_and_lists_undeclared_edges`, `test_an_endpoint_that_is_only_an_interned_constant_is_a_label_gap` (the 4901 shape on the fixture, attributed to its dataset), `test_a_subclass_in_the_ancestry_satisfies_the_declared_label`, `test_an_id_written_under_two_labels_is_a_collision` and `test_the_cli_takes_a_schema_and_reports_label_gaps`, each against a small schema yaml written under `tmp_path`.
