## 2026.10.11 - Released SGA systematic names that R64-4-1 no longer carries (#893, #897)

Shared by the Costanzo 2016 and Kuzmin 2020 loaders, whose releases name every strain by the ORF the SGA deletion collection was built against. Test file: `tests/torchcell/datasets/test_systematic_name_currency.py`; the hermetic loader tests inject `tests/torchcell/datasets/_sga_genome_stub.py`, a genome on which every pin and refusal below holds.

51 distinct released names are not live loci of R64-4-1 (35 in Costanzo 2016, 47 in Kuzmin 2020, 31 shared, so 82 store occurrences). Each is decided by one rule, and the decision is re-checked against the injected genome when a loader builds:

| Class | Count | Rule | Outcome |
|---|---:|---|---|
| renamed | 16 | SGD's locus history of the current ORF records the released name as that ORF's former systematic name, changed for nomenclature; R64 lists the released name as an `Alias` of that ORF alone, and the name is not itself a live gene | mapped to the current ORF through a `PinnedAliasResolution` with rule `sgd_systematic_rename` (`gene_alias_resolution.check_pin`) |
| merged | 28 | R64 keeps the released ORF only as an `Alias` of a longer locus (24 genes, 3 blocked reading frames, 1 pseudogene); SGD's history states the merge for the 24 genes, and every release naming the ORF also carries a separate deletion strain of the locus | refused, `merged_into_locus`: the released strain deleted part of the locus, not the locus |
| retired | 7 | R64 carries no locus ID, `gene=` or `Alias=` value for the name | refused, `retired_systematic_name` |
| anything else not live | 0 | | the build stops with `not_current_unpinned` |

"Live" is the R64 resolver's `current`, or `non_gene_feature` resolving to itself (a pseudogene or blocked reading frame named by its own ID), the same test the `canonical_gene_names` verifier rule applies.

Why the GFF alone does not decide: a renamed and a merged ORF look identical in the R64-4-1 GFF (both are an `Alias=` of one locus). The event type is in SGD's per-locus history, read from the locus JSON that `SCerevisiaeGenome` cached under `$DATA_ROOT/data/sgd/genome/genes/<ORF>.json` (file mtime 2025-08-28). No SGD call is made: each pin carries that file's sha256 and a verbatim quote of one `locus.history[].note`, and `test_every_pin_matches_its_source_bytes` re-reads both when `DATA_ROOT` holds them. The four merges into non-gene loci have no cached locus JSON; their quote is the locus's row of the genomes-tier GFF (`R64_GFF`, sha256 `64f61e3153083a8ef6d853721c9e83e4469cdc120883ec281e51a0df4ba390fa`), and the merge rests on the alias plus the release's separate strain of the locus.

A row is refused when any checked column names a refused ORF. Loaders apply the check after their reference noise is computed, so the reference remains the release's statistic and no kept record changes. Each build writes `preprocess/systematic_name_ledger.json` (`SystematicNameLedger`: rows in, refused, out, and per name the stored name or the refusal reason and locus); the model refuses a ledger whose counts do not add up.

The per-name evidence (resolver status, locus type and class, the strain ids of each ORF and of its locus in both releases, rows per store) is generated by `experiments/036-dataset-fixes-before-kg-build/scripts/yeast_gene_id_currency.py`; see [[experiments.036-dataset-fixes-before-kg-build.scripts.yeast_gene_id_currency]].
