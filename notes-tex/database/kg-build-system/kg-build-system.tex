\begin{abstract}
\noindent
A knowledge-graph store is built on one host from the development LMDBs, under
slurm, from a commit that carries a package tag; it is stamped with a release id
and a \texttt{KgRelease} node, swapped into the serving container, and written out
as an online backup that the archive on Taiga holds beside its manifest and
checksums. A package version and a store are used only as a pair: the build
refuses an untagged commit, the client refuses a store whose schema contracts the
installed package does not reproduce for every dataset, the committed snapshots
drive a pairs table that CI holds current, and \texttt{ops.sh sync} fails when two
hosts serve different releases. The build host is GilaHyper today and is the one
replaceable box in the diagram: the artifact it produces, the archive, and the
deploy step that restores an artifact into any serving host do not depend on
where the build ran. Radiant cannot serve a release yet, because Neo4j does not
run a store on NFS and the VM has no other disk; the fix is a block volume and
one \texttt{deploy} command.
\end{abstract}
