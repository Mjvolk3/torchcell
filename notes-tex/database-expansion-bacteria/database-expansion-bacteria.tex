\noindent
The database holds 51 schematized and L0--L4-verified \org{Saccharomyces cerevisiae}
datasets and no bacterial dataset at all. Table~\ref{tab:bfinal} ranks 75 candidates for
the two bacterial hosts, \org{Escherichia coli} and \org{Pseudomonas putida}, by
measurements, meaning instances times phenotype dimensionality (Sec.~\ref{sec:rule}); the
first fifty are the recommended builds and the remaining 25 are a ranked reserve. The
build is staged in two tranches, twenty rows then thirty, with a floor of six rows per
host in the first tranche so that neither host's setup cost waits on the other
(Sec.~\ref{sec:stage}). Of the fifty, 39 are \org{E. coli} and 11 are \org{P. putida}.

One consequence of that ordering is large enough to state before the table rather than
after it (Sec.~\ref{sec:cost}). The rows that connect an engineering intervention to a
production phenotype carry a median of 145 measurements against 282,906 for the
functional-genomics screens, so twenty-one of the twenty-four engineering rows fall into
the reserve. The ranking is reported as specified, and the records carry the class field a
portfolio rule would need to reorder them.

Two changes to the schema gate every row, and both were established by running the
validators rather than by reading them (Sec.~\ref{sec:schema}): the gene-identifier
namespace rejects every bacterial gene name, and the genomes tier has no bacterial
assembly set. A third thing expected to block turns out not to, since the reference genome
record already accepts either host unchanged.

Table~\ref{tab:banalogs} is the column that answers whether these rows fit the record
types already in use: for each one, the built yeast dataset it mirrors and what the
loader would still need. Table~\ref{tab:bsources} gives each row's citation, link and
data location; Table~\ref{tab:bexcluded} records what was considered and dropped;
Sec.~\ref{sec:summary} closes with the summary statistics and the confidence split.
