## 2026.10.12 - Removals since KG 3.0 (4b293d343), reviewed against the trust-the-old-schema rule

Owner request, 2026-10-12, verbatim: "we should land all schema breaking updates ... but now i am thinking you have made some bad decisions wrt to removing items ... i would like a review if you have unnecessarily removed... also we trust old schema by default because we know compute went into building it."

The rule applied to every row: the KG 3.0 schema and the KG 3.0 served records are trusted by default. A removal (a class, an enum member, a field, a dataset class leaving the registry or the KG mapping, or records a loader used to store) needs a correctness argument. "The required field is missing in the source" is not by itself one; the route for that is a typed provenance gap on the carrier. Verdicts:

- `justified`: the removed thing was wrong, duplicated, or impossible to represent honestly.
- `unnecessary`: a typed gap, a sibling leaf, a flag, or a library entry (an additive change) would have kept it.
- `owner`: a judgment call only the owner should make.

Scope: the 616 commits `4b293d343..eb07bd213` on `origin/main`, the open dataset PR #985 as pushed (head `904643bbc`), and the other open PRs that touch `torchcell/datamodels`, `torchcell/datasets`, `torchcell/adapters` or `torchcell/knowledge_graphs` (#762 removes a schema widening; #1041, #648, #455 and #414 remove nothing in scope; #1041 landed as 35769decd while this audit ran and removes nothing). This is a review of the record: counts are the ones the commits, PRs and notes state, and no store was re-measured. Tracking issue: #1045 (labels `dataset`, `before-next-kg-build`).

### Method and what it found at the surface

- **Schema symbols.** An AST diff of every module in `torchcell/datamodels/`, `torchcell/adapters/`, `dataset_registry.py` and `dataset_adapter_map.py` (classes, class-body fields and enum members, methods, module constants, and the members of every union alias such as `PhenotypeType`, `GenePerturbationType` and `ExperimentType`), once over the whole range and once per commit. Net from KG 3.0 to head, the only removed schema symbols are the 12 pointer fields that `ArtifactRef` replaced and one renamed constant. **No enum member was removed from any shared enum**: none of the 19 enum classes `schema.py` had at KG 3.0 (among them `MeasurementType`, `ConcentrationUnit`, `PreCultureSource`, `DoseBasis`, `SampleUnit`, `AssayType`, `UncertaintyType`, `PhysicalFactor`) lost a member, nor did the enum in `compound_identity.py`; there are 33 in `schema.py` now. The one enum removed, `SourceWithdrawalReason`, was added the day before. No union alias (`PhenotypeType`, `GenePerturbationType`, `ExperimentType`, `ExperimentReferenceType`, `EnvironmentPerturbationType`) lost a KG 3.0 member; inside the range `PhenotypeType` lost `PseudobulkUmiCountPhenotype` (row 11) and `GenePerturbationType` lost `BacterialIntergenicVariantPerturbation` (row 8), both added in the range. No field annotation of a KG 3.0 class was narrowed; two were widened to `| None` (`BacterialDegronPerturbation.terminus`, `SingleCellExpressionPhenotype.cell_cycle_stage_counts`), both on classes added in the range.
- **Fingerprint check.** `PYTHONPATH=<worktree> python scripts/schema_impact_check.py --base 4b293d343` on head reports 162 changed symbols; the only `BREAKING` entries are the six classes that lost the pointer fields (`CopyNumberVariantPerturbation`, `CrisprConstruct`, `NaturalGeneAbsencePerturbation`, `NaturalGenePresencePerturbation`, `SegregantParent`, `SequenceVariantPerturbation`) and the removed `SYSTEMATIC_GENE_PATTERN` binding. Every other KG 3.0 symbol it lists only gained members, optional fields or validators; the four changed validators on KG 3.0 classes (`BackgroundAllele`, `ProvenanceGapMixin`, `SegregantGenotype`, `StrainBackground`) were read and none refuses a value it accepted before (the constant rename, per-key gaps, a relaxed block check, and the new `integrations` field).
- **Graph schema.** `biocypher/config/torchcell_schema_config.yaml` lost one property, `effector_plasmid_uri` (renamed `effector_plasmid_ref`); every other removed line is a `source:` or `target:` widened to a list. No node class served by KG 3.0 was removed.
- **Registry and KG mapping.** All 52 dataset classes registered at `4b293d343` are still registered (154 now); all 51 dataset classes in the KG 3.0 `dataset_adapter_map` are still mapped (154 now); no `torchcell/knowledge_graphs/conf/*.yaml` lost a line. The only registry removals in scope are the three in PR #985.
- **Media and compounds.** No `MEDIA_LIBRARY` key was removed and no pre-existing media digest in `tests/torchcell/datamodels/test_media_bacterial.py` was re-pinned. `experiments/036-dataset-fixes-before-kg-build/scripts/compound_identity_table_diff.py --old <4b293d343 table> --new <head table>`: 5,498 to 5,723 records, 285 keys added, **0 keys removed, 0 renamed, 0 lost, 0 identifier changes**. Run per commit, two case-only renames appear inside the range (row 13).
- **Stores.** No KG 3.0 store was retired or renamed. The top-level `*.deprecated-2026-09-12*` directories under `$DATA_ROOT/data/torchcell/` predate KG 3.0. Inside the range the renames are rebuild set-asides (`processed.superseded.<ts>`, `preprocess.superseded.<ts>`, from 98d72bad4 "retiring the old store by rename") plus `inhibitor_bioscreen_volk2021.superseded.20261008-032554` (private, a rebuild). The entries the graveyard `/scratch/projects/torchcell-deprecated/` gained since 2026-10-06 are rebuild set-asides of datasets added in the range.
- **Out of scope, checked.** The 2026-10-06 retirement of 109 unreached modules (90227060b, e6367528b) and the root cleanup (8464bb9b0) removed code that registered no dataset class and defined no schema symbol.
