### C2. GEO's `VALUE` column definition, and whether it is log2(deletion/refpool) or log2(refpool/deletion), and the same on "-a" and "-b" arrays

- Previously stated by: main note, "VALUE Column Convention": "VALUE = log2(Cy3/Cy5) = log2(refpool/deletion)"; old loader `_validate_log2_ratios` docstring (lines 1929-1935) and comment at 1996; worktree note 2026.09.28 bullet 4 (mixed definitions).
- Verdict: REFUTED as a single convention. VALUE is log2(deletion/refpool) on 2169 of 2633 deletion arrays and log2(refpool/deletion) on 464; the `#VALUE` label is wrong on 465 arrays.
- Evidence:
  - Verbatim `#VALUE` lines from live GEO (2026-09-29): GSM630105 (-a) and GSM630106 (-b): `#VALUE = normalized log2 ratio test/ref`; GSM1107978 (-a): `#VALUE = normalized log2 ratio (Cy3/Cy5)`; GSM1107979 (-b): `#VALUE = normalized log2 ratio (Cy5/Cy3)`; GSM636381 (-c): `#VALUE = dye bias corrected normalized log2 ratio (Cy3/Cy5)`; GSM636342 (-d): `#VALUE = dye bias corrected normalized log2 ratio (Cy5/Cy3)`; GSM819599 (`pfk1-del-2-c1`): `#VALUE = -INV_VALUE: normalized log2 ratio Cy3/Cy5 test/ref)`; GSM819600 (`pfk1-del-2-c2`): `#VALUE = normalized log2 ratio Cy3/Cy5 test/ref`. Eight distinct strings occur across the two deletion series (raw files: 466 + 461 + 131 + 131 + 114 + 42 + 42 in GSE42527; 493 + 471 + 168 + 29 + 28 + 28 + 28 + 1 in GSE42526). By label the "-a" arrays are mostly "(Cy3/Cy5)" and the "-b" arrays mostly "(Cy5/Cy3)", so by label VALUE is test/ref on both; the definition is not the same string on -a and -b.
  - Numerically (`kemmeren_full_pass.py`, every array, all 15552 rows): VALUE reproduces log2(`Signal Norm_Cy3`/`Signal Norm_Cy5`) or its negative to machine precision on 2632 of 2633 arrays (the one exception, GSM1107527 `[hs1991] opi3-del-1-a`, correlates at -1.000 with log2(Cy3/Cy5) but is not an exact copy). Relative to GEO's own channel assignment, VALUE = log2(deletion/refpool) on 2169 arrays and log2(refpool/deletion) on 464 (232 in each series). The 464 are almost all "-a" arrays of the `[hs1990]`/`[hs1991]` resubmission batches labeled "normalized log2 ratio (Cy3/Cy5)" whose numbers are log2(Cy5/Cy3) (462 such arrays; cross-tab: of 937 arrays labeled "(Cy3/Cy5)", 475 are numerically Cy3/Cy5 and 462 are Cy5/Cy3), plus two "test/ref"-labeled arrays that are ref/test (GSM630089 `abc1-del-2-a` is one: VALUE at ABC1's own probes +3.144, +3.166) and one "(Cy5/Cy3)"-labeled array that is Cy3/Cy5. Examples: GSM1107223 `[hs1991] dbp3-del`, labeled "(Cy3/Cy5)", VALUE at DBP3's probes +3.08, +3.01; GSM1107711 `[hs1991] sam3-del-1-e`, labeled "(Cy3/Cy5)", VALUE at SAM3 +4.40, +4.43. Within the resubmitted batches, 445 of 917 "-a" arrays carry VALUE = ref/del and 3 of 928 "-b" arrays do; in the original batches 2 of 360 "-a" arrays do.
- Consequence for the loader / served records: none directly, because neither loader reads VALUE (the old loader falls back to VALUE only when the `Signal Norm_*` columns are absent, and all 2633 arrays have both: 1695 with `ID_REF, Signal Norm_Cy5, Signal Norm_Cy3` and 938 with an extra `INV_VALUE`). The old `_validate_log2_ratios` "correlation 1.000" compared log2(Cy3/Cy5) with VALUE on the first 20 genes' first arrays, which only checked which column ratio VALUE copies. Any consumer that used VALUE as log2(mutant/WT) would have 464 arrays sign-flipped; the deleteome's own published M values are not affected by this, since they come from the authors' limma run, not from this column.

### C3. The old loader's title rule assigned the deletion to the wrong channel on most arrays, and a second negation made the served log2 sign right on most records anyway; re-derive the stored sign for "-a" and "-b" arrays

- Previously stated by: main note 2026.09.27 section; worktree note 2026.09.28 "What the served records hold"; issue #459 bullets 3 and 4.
- Verdict: CONFIRMED.
- Evidence (code, old loader): `_extract_expression_from_gsm_static` line 902-910: `if "-a" in title or "_a" in title or title.endswith("a"): expression_column = "Signal Norm_Cy5"`, `elif "-b" ... : "Signal Norm_Cy3"`, else `"Signal Norm_Cy5"`; `_extract_refpool_from_deletion_samples_static` 951-961 takes the other column and averages it over the gene's arrays; `create_expression_experiment` line 2152: `log2_ratio = -np.log2(rep_value / refpool_expression[gene])`, with the comment at 2149-2151 "GEO stores log2(refpool/deletion) ... We negate".
  - Derivation with C1: on a "-a" array GEO has reference = Cy5, deletion = Cy3. The old loader calls Cy5 the deletion (it is the reference) and Cy3 the refpool (it is the deletion), so `rep_value` = reference signal and `refpool_expression` = mean deletion signal over the gene's arrays; the stored value is -log2(reference / mean deletion) = log2(mean deletion / reference), the right sign. On a "-b" array GEO has deletion = Cy5, reference = Cy3; the old loader takes Cy3 (the reference) as deletion and Cy5 (the deletion) as refpool; stored = -log2(reference / mean deletion), again the right sign. On any array that falls to the default (no "-a"/"-b" in the title) the loader takes Cy5: on a "-c" array (reference in Cy5) that is the reference, sign right; on a "-d" array (deletion in Cy5) that is the deletion, stored = -log2(deletion / mean reference), sign wrong. On the three reversed-metadata genes (rcm1, rps0b, rps21a) the title rule happens to pick the true deletion on both arrays, so both are sign-flipped. On `[hs1991] yil014c-a-del-1-b` the substring "-a" in the gene name wins, Cy5 is taken, which is the deletion on that "-b" array, sign wrong.
  - Counts (`kemmeren_full_pass.py`): the old rule's column equals the reference channel on 2594 arrays (sign right after negation) and the true deletion channel on 39 (sign wrong): 29 "-d" arrays, `pfk1-del-2-c1`, `[hs1991] ctf8-del-3-g`, `[hs1991] lsm12-del-3-e`, the six rcm1/rps0b/rps21a arrays, and `[hs1991] yil014c-a-del-1-b` (full list in `kemmeren_full_pass.out`). The 25 "-c" arrays are NOT flipped. Affected mutants: 6 with every array flipped (YDR009W gal3, YDR223W crf1, YIR013C gat4, YKR057W rps21a, YLR048W rps0b, YNL022C rcm1) and 30 with one of two arrays flipped (YAR042W, YBL019W, YCR084C, YDR097C, YDR156W, YDR259C, YEL018W, YER110C, YGL241W, YGR240C, YHR121W, YHR191C, YIL014C-A, YIL073C, YIL153W, YJL115W, YKR034W, YLR385C, YML036W, YML082W, YMR072W, YMR234W, YNR004W, YOR140W, YOR162C, YOR290C, YOR295W, YPL274W, YPR135W, YPR152C), 36 records in all, every one present in the dev LMDB. Under the old rule the deleted gene's own probes read negative on 2420 of 2479 ORF-matched arrays (0.976), against 2458 under GEO's labels.
  - Single-array numeric check (`kemmeren_array_numeric_check.py`): `bck1-del-1-a` old-rule stored self log2 -3.647 (right); `bck1-del-1-b` -3.197 (right); `asf1-del-1-d` +3.160 (flipped); `pfk1-del-2-c1` +4.473 (flipped); `pfk1-del-2-c2` -4.831 (right); `[hs1991] yil014c-a-del-1-b` +2.032 (flipped); `[hs1991] dbp3-del` -3.044 (right, reference in Cy5 so the default is the reference).
  - Two further consequences of the old code, both confirmed by reading it: the linear `expression` stored per record is the mean of the column the loader called deletion, which is the reference signal on 2594 arrays, and the reference's `expression` is the mean deletion signal (lines 2176 and 2198); and because the denominator is the mean of the other column over the gene's arrays rather than the same array's value, the per-array log2 ratios and their SE are not within-array statistics (the worktree note measured the SE effect; not re-measured here).
- Consequence for the loader / served records: the served `expression_log2_ratio` has the right sign on 1448 of 1484 records and the wrong or cancelled sign on 36 (the worktree note and issue say 35 and say rcm1 is "not in the LMDB"; both are corrected below). The fixed loader removes the title rule and the negation and takes log2(deletion / refpool) within each array.

### C4. The paper's design: dye-swap pairs per mutant, biological replicates per deletion, how the reference pool was made, how the reported log2 fold change (M) and p value are computed

- Previously stated by: old loader header comments lines 50-89 (quotes dated 2026-01-27); main note 2026.01.29 section.
- Verdict: CONFIRMED for the paper's design; the loader's paraphrase of "four measurements" is wrong (New findings, item 5).
- Evidence, verbatim from `paper.md`:
  - Line 130 (Experimental Procedures, Expression Profiling): "Each mutant strain (Table S1) was grown twice, from two independently inoculated cultures. Cultures were harvested early during exponential growth in SC medium with 2% glucose. Each culture was expression-profiled in technical replicate to yield four measurements for each profiling mutant. To monitor reproducibility, a common reference design was adopted with a batch of WT RNA applied in dye-swap to one of the channels of each microarray (Figure S1B). Additional WT cultures were grown alongside batches of mutants on each day and profiled in parallel to monitor batch effects and to generate the set of WT transcriptomes for comparison to mutants."
  - Line 307 (Extended Experimental Procedures, Experiment Design): "Two channel microarrays were used. RNA isolated from a large amount of WT yeast was used in this common reference design, in one of the channels for each hybridization and used in the statistical analysis to obtain an average expression-profile for each deletion mutant relative to the WT. Two independent cultures were hybridized on two separate microarrays. For the first hybridization the Cy5 (red) labeled cRNA from the deletion mutant is hybridized together with the Cy3 (green) labeled cRNA from the common reference. For the replicate hybridization from the independent cultures, the labels are swapped. Each gene is represented twice on the microarray, resulting in four measurements per mutant."
  - GEO series overall design (GSE42527 and GSE42526, fetched 2026-09-29): "RNA isolated from a large amount of wt yeast from a single culture was used as a common reference."
  - Line 32 (Results): "This included four replicates per responsive mutant, robotic procedures optimized with external calibration controls (van Bakel and Holstege, 2004), a common reference design with wildtype (WT) reference RNA applied in dye-swap to each microarray (Figure S1B), as well as dye-bias correction (Margaritis et al., 2009) and spike-in controls to monitor global changes (van de Peppel et al., 2003). Additional WT cultures were processed alongside batches of mutants, with day-specific effects countered by regrowing the entire batch. Statistical modeling results in an average expression profile for each mutant. Each profile consists of p values and average transcript level changes in the mutant relative to 428 WTs."
  - Line 388 (Statistical Analysis of Expression Profiles): "For each mutant the replicate hybridizations from two independent cultures were compared to the WT cultures grown on the same day to control for day-specific effects (described above) and to a pool of WT replicates collected throughout the project to generate the final mutant expression-profile (p value and fold-change in mutant versus average WT). For the MATalpha mutants grown on the Tecan plate shaker, the WT pool consisted of 200 MATalpha WTs (BY4742, ArrayExpress accession E-TABM-984, GEO accession GSE42217). For the MATa mutants grown on the Tecan plate shaker, the WT pool consisted of 20 WT-MATa replicates (BY4741, ArrayExpress accession E-MTAB-1351, GEO accession GSE42241).   - Line 394: "During the course of the project it became clear that a significant fraction of mutants were similar to WT. From that stage on, in order to reduce costs, first only one of the two replicate cultures was processed. Based on this it was decided whether the second culture should be processed. Selection was based on the amount of significant changes (> 8) in the analysis of the single culture. This entails that for some of the nonresponsive mutants there are four replicate measurements while for others there are only two. The average of all the responsive mutants is based on four measurements."
  - Line 50 (Figure 2B legend): "standard deviation of M, the log2 (mutant/WT), across all mutants, plotted as a function of A, the log2 expression level (fluorescent intensity) from 200 WTs"; line 347: "M (log2(R/G)) ratios"; line 368-378: print-tip LOESS normalization and the GASSCO gene-specific dye-bias correction `M_ij = M*_ij - iGSDB_i x F_j`.

### C5. GPL11232 has two probes per ORF; the paper's/platform's reason and what the paper does with them

- Previously stated by: issue #459 comment (2026-09-28); worktree note 2026.09.28 "The fix", last bullet.
- Verdict: PARTLY CONFIRMED. Two probes per ORF is confirmed from the platform table and the paper; the paper gives no explicit reason and does not describe averaging; the two spots are the "four measurements" that enter its limma model.
- Evidence:
  - Platform GPL11232 (`A-UMCU-Y16k-1.3`, `!Platform_data_row_count = 15552`, fetched 2026-09-29): 12362 rows have an `ORF` value, 6169 unique; of the 6140 that match the systematic-name pattern, 6128 occur exactly twice and 12 four times. `#ORF = ORF Name ...`, `#GENE_SYMBOL = Gene symbol for the gene`, `#REPORTER_GROUP = class the reporter belongs to, e.g. controls or genes`. The remaining rows are `ex_control`, `qc_control` and unnamed spots.
  - Paper line 311: "Each gene probe is spotted twice on the array, which contain an additional 2,838 control features for spike-in external control normalization and quality control (van de Peppel et al., 2003)." Line 307: "Each gene is represented twice on the microarray, resulting in four measurements per mutant." GEO series overall design says the same. Line 394: "The average of all the responsive mutants is based on four measurements." The limma citation at line 390 is Smyth et al. 2005, whose title in the reference list (line 481) is "Use of within-array replicate spots for assessing differential expression in microarray experiments". No sentence in the paper says "averaged" for the duplicate spots. Hypothesis (untested, from the citation only): the two spots were handled by limma's within-array replicate-spot model (duplicateCorrelation).
