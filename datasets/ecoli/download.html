Downloading the E. coli archives

The four E. coli datasets of The E. coli datasets are served as archives by the tc-data endpoint. A loader constructed with TC_DATA_URL set downloads its archive, checks the sha256, unpacks the store, and opens the records, so no build step and no source file is needed. This page covers what the endpoint serves, what a download leaves on disk, how long it takes, and how to check the records against the knowledge-graph release. The endpoint’s routes, the other file tiers and the curl commands are in Downloading datasets. The code blocks are parts of the tutorial script, ecoli_download_tutorial.py.

Terms used below:

  • archive: one tar.xz file holding one store, named <slug>-<torchcell version>-<first eight hex digits of its sha256>.tar.xz.

  • content hash: the sha256 over the sorted experiment ids of a dataset. An experiment id is the sha256 of one record’s experiment, and each knowledge-graph release records one content hash per dataset.

  • slug: the directory name of a store, which is also the dataset’s name on the endpoint.

  • store: the built form of a dataset. Its processed/ directory holds the records LMDB and the interned LMDB beside it, and its preprocess/ directory holds the build manifest and the tables the loader wrote.

Set the endpoint

import hashlib
import json
import os
from pathlib import Path
from typing import Any

import numpy as np
import pandas as pd

from torchcell.datasets.artifact import content_sha256
from torchcell.datasets.client import DatasetClient
from torchcell.datasets.ecoli.babu2014 import GeneInteractionBabu2014Dataset
from torchcell.datasets.ecoli.campos2018 import (
    FEATURE_UNITS,
    MORPHOLOGY_ASSAY,
    GrowthRateCampos2018Dataset,
    MorphologyCampos2018Dataset,
)
from torchcell.datasets.ecoli.fuhrer2017 import MetabolomeFuhrer2017Dataset
from torchcell.endpoint_http import DEFAULT_URL

# A loader downloads its built store only when TC_DATA_URL is set. Without it the loader
# builds the store from the publisher's files, which is the developer path.
os.environ.setdefault("TC_DATA_URL", DEFAULT_URL)

DATA = Path("data/torchcell")  # each dataset unpacks into DATA/<slug>/
pd.set_option("display.precision", 4)


def brief(value: Any, depth: int = 1) -> Any:
    """A record part with anything nested deeper than ``depth`` replaced by its size."""
    if isinstance(value, dict):
        kept = {k: v for k, v in value.items() if k != "provenance_gaps"}
        if depth < 0:
            return f"<{len(kept)} fields>"
        return {k: brief(v, depth - 1) for k, v in kept.items()}
    if isinstance(value, list):
        return f"<{len(value)} items>" if value else []
    return getattr(value, "value", value)  # an enum member prints as its value


def show(part: dict[str, Any]) -> None:
    """Print one part of a record as indented JSON, two levels deep."""
    print(json.dumps(brief(part), indent=2, default=str))

DEFAULT_URL is the public endpoint. It takes no key and no account. A loader downloads only when TC_DATA_URL is set in the process environment. With the variable unset, the same constructor builds the store from the publisher’s files, which needs the raw-file mirror of a development machine.

select returns the newest archive whose torchcell_version shares the installed major.minor, and None when the endpoint has no such archive. An archive name includes the version it was packaged with, and every release on that major.minor line reads it.

Download by constructing a loader

growth = GrowthRateCampos2018Dataset(root=str(DATA / "ecoli_growth_rate_campos2018"))
print(f"{len(growth):,} records")

3,664 records

The constructor did the download. After it returns, data/torchcell/ecoli_growth_rate_campos2018/ holds the archive under artifacts/ and the store under processed/ and preprocess/. A second construction with the same root opens the store without a request. The other three loaders work the same way, each with its own slug as the directory name.

Check the records against the release

The endpoint’s index row holds the content hash the knowledge-graph release recorded for the dataset. Hashing the loaded records the same way reproduces it when the download holds exactly the records the graph serves.

def experiment_id(record: dict[str, Any]) -> str:
    """The id the knowledge graph gives this record: sha256 of its experiment."""
    return hashlib.sha256(json.dumps(record["experiment"]).encode("utf-8")).hexdigest()


for slug, dataset in loaded.items():
    ids = (experiment_id(dataset[i]) for i in range(len(dataset)))
    digest = content_sha256(ids)  # one hash over every record of the dataset
    served = client.select(slug).content_sha256  # what the release recorded
    print(
        f"{slug}  {digest}  {'matches' if digest == served else 'DIFFERS FROM'} the release"
    )

The archives were packaged by scripts/package_dataset_lmdb.py from the stores the loaders built.

Caveats

A loader builds instead of downloading when TC_DATA_URL is unset. torchcell does not read a .env file by itself, and the built-in DEFAULT_URL does not switch a loader to the download. Set the variable in the shell or in the process before the first constructor, as the setup block does.

An archive is tied to a major.minor line. select returns None for an installed version on another line, and the loader then raises and names the slug. It does not fall back to building.

torchcell 1.8.4 and earlier need torch-scatter before a loader imports. From 1.8.5 the loaders import without it (Install timings and release checks).
