## 2026.10.11 - Pinned dump, whole-gene alleles, carried conditions, no guessed medium (#901) [the loader half superseded the same day, see below]

Every number below is measured from pinned bytes by `experiments/036-dataset-fixes-before-kg-build/scripts/sgd_synlethdb_findings.py` (results `experiments/036-dataset-fixes-before-kg-build/results/sgd_synlethdb_findings.json`). The source is SGD's per-gene API dump, `$DATA_ROOT/data/sgd/genome/genes`, 6,607 JSON files written by `torchcell.graph.sgd.main_get_all_genes` on 2025-08-28, pinned by `SGD_GENES_DIGEST` = `1cb4ed59556b1534e28eb79ad21135cdb5a149f78dca8df4924f473e39eef409` (sha256 over the sorted `"<file name> <file sha256>"` lines; the same pin the #889 verifier uses).

### What the loader does now

- It reads the pinned JSON files itself and refuses a missing dump or bytes off the pin (`SgdDumpDigestError`). It no longer walks the `G_raw.pkl` graph cache, no longer downloads a fresh dump when fewer than 100 files are present, and takes no `scerevisiae_graph` argument (the frozen 006 and 010 experiment scripts that pass one are stale callers).
- One record per inviable / null / S288C annotation whose allele is SGD's whole-gene deletion `<gene>-Δ` (U+0394; one annotation spells it U+2206, `yil102c-A-∆`, folded as the same name). Every other allele is ledgered in `preprocess/dropped_records.json` (`SgdDropLog`: SGD annotation id, allele, PubMed id, condition, note) and never stored. A repeated (gene, condition, PubMed id) key refuses the build.
- Condition properties are carried by a closed vocabulary of the dump's four verbatim (class, text) pairs (`SGD_CONDITIONS`); any other pair refuses the build (`SgdConditionError`).
- The medium and temperature an annotation does not state are `ProvenanceGap`s (`not_carried_by_curation`, `looked_in` the pinned dump), on the new `Environment.media` gap ([[torchcell.datamodels.schema]]).
