## 2026.09.18 - Single-mutant fitness of the ten deleted factors

The 008 document reports trigenic interactions among ten transcription-factor deletions
(FKH1, GCN5, MED4, OPI1, RFX1, RGR1, RPD3, SPT3, TFC7, YAP6) read out on fatty acid titer
in a pox1 faa1 faa4 chassis (Xue et al. 2025). This section records what each of those ten
deletions costs in growth on its own, as measured by the yeast genetic-interaction screens.
Generated by `experiments/008-xue-ffa/scripts/tf_single_mutant_fitness.py`, which reads the
raw tables directly and writes
`experiments/008-xue-ffa/results/tf_single_mutant_fitness.csv` (one row per gene x source x
strain) and `experiments/008-xue-ffa/results/tf_single_mutant_fitness.tex` (the table body).

Fitness in every source below is relative to wild type = 1.

### Where each value came from

- **Costanzo et al. 2016**, file
  `$DATA_ROOT/data/torchcell/smf_costanzo2016/raw/strain_ids_and_single_mutant_fitness.xlsx`,
  columns `Single mutant fitness (26°)` / `Single mutant fitness (26°) stddev` and
  `Single mutant fitness (30°)` / `Single mutant fitness (30°) stddev`. The stddev column is
  a bootstrap SE, not a colony SD, and the resampling unit is the control screen.
- **Kuzmin et al. 2018**, file
  `$DATA_ROOT/data/torchcell/smf_kuzmin2018/raw/aao1729_data_s1.tsv`, columns
  `Array single mutant fitness` and `Query single/double mutant fitness`. The query column
  is a single-mutant fitness only on rows where `Combined mutant type` is `digenic`; on
  trigenic rows it is the fitness of the double-mutant query. None of the ten appears as a
  query strain in this file, so every Kuzmin 2018 value here is an array value.
- **Kuzmin et al. 2020**, files `aaz5667-Table-S5.xlsx` (the table `SmfKuzmin2020Dataset`
  consumes; rows with `Mutant type` == `Single mutant`, columns `Fitness` and `St.dev.`)
  and the `Array single mutant fitness` column of `aaz5667-Table-S1.xlsx` and
  `aaz5667-Table-S3.xlsx`, all under
  `$DATA_ROOT/data/torchcell/smf_kuzmin2020/raw/`.
- **Essentiality** from the mirrored SGD gene records
  `$DATA_ROOT/data/sgd/genome/genes/<ORF>.json`, using the rule
  `GeneEssentialitySgdDataset` applies: a `phenotype_details` entry with `mutant_type`
  `null` and phenotype `inviable`. The strain of that record is reported, because a
  null-inviable record in a non-S288C background is weaker evidence than one in S288C.

### Which genes are essential, and how each screen handled them

- **MED4 (YOR174W)** and **RGR1 (YLR071C)** carry an SGD null-inviable record in S288C.
  Neither has a deletion strain in any of these screens, exactly as expected. Costanzo
  represents MED4 by two temperature-sensitive alleles, `med4-6` (strains `YOR174W_tsa738`
  and `YOR174W_tsq738`, the same allele in the array and query collections) and `med4-54`
  (`YOR174W_tsq956`, no fitness reported). It represents RGR1 by a DAmP allele
  (`YLR071C_damp750`) and the ts allele `rgr1-100` (`YLR071C_tsa908`, `YLR071C_tsq1208`).
  The two allele classes disagree sharply for RGR1: the DAmP strain is near wild type at
  0.974, while the ts allele sits at 0.501 at 26 C. A DAmP allele knocks down expression
  rather than removing the protein, so these are two different perturbation strengths of
  the same gene, not two measurements of one quantity.
- **TFC7 (YOR110W)** has an inviable null phenotype recorded by classical genetics in a
  strain SGD labels `Other`, and no S288C null-inviable record, so the S288C rule alone
  would call it non-essential. The screens treat it as essential: the only TFC7 strain in
  Costanzo is the DAmP allele `YOR110W_damp967`, with no deletion strain anywhere, and no
  fitness value is reported for it in either temperature column.
- The remaining seven are represented by deletion strains (KanMX `dma`, NatMX `sn`) where
  they appear at all, consistent with their lack of a null-inviable record.

### Genes absent, or present without a value

- **GCN5 (YGR252W) is absent from every source checked.** No strain in the Costanzo SMF
  table, no array or query strain in Kuzmin 2018, and nothing in Kuzmin 2020 Tables S1, S3
  or S5. There is no single-mutant fitness for GCN5 to report from these screens.
- Every absence is cross-checked. The lookup is keyed on systematic name, so the script also
  searches each file's allele-name column for the gene name and reports any hit whose ORF
  differs, which would mean a strain filed under an unexpected ORF. Nine of the ten come
  back clean. The four OPI1 hits are the prefix collisions `opi10` (YOL032W, strains
  `dma4317` and `sn3639`) and `opi11` (YPR044C, strain `dma5042`), which are different
  genes, so no gene is filed under an ORF the lookup missed.
- **RPD3 (YNL330C)** has a strain in the Costanzo table, the NatMX deletion `YNL330C_sn1795`,
  but both fitness columns are empty for it, and RPD3 appears in no Kuzmin table. Strain
  present with no value is a different statement from absent, and the CSV keeps them apart.
- **TFC7** is the same case: `YOR110W_damp967` exists, with no fitness reported.
- **SPT3** has no Kuzmin 2020 entry, and **RGR1**, **RPD3**, **TFC7**, **YAP6** have no
  Kuzmin 2018 array entry.
- The Kuzmin 2020 query columns were not scanned, because on trigenic rows that column is a
  double-mutant fitness. The one relevant digenic query row, `YDR259C+YDL227C_tm691`
  (`yap6Δ+hoΔ`) in Table S1, carries no fitness value, and the single-mutant fitness for
  YAP6 is the Table S5 row `tm691` at 1.0069 (0.0040).

### Reading the numbers

- Two of the ten carry a large growth defect in these screens, and both are essential genes
  measured through a hypomorphic allele rather than a deletion: MED4 at 0.52 (26 C) / 0.42
  (30 C) and RGR1 at 0.50 (26 C) / 0.53 (30 C) through `rgr1-100`. The Xue panel deletes
  these genes, so neither screen value is a measurement of the strain in that panel.
- SPT3 is the one clear deletion defect, 0.726 in Costanzo and 0.719 in Kuzmin 2018.
- OPI1 is mildly sick (0.855), RFX1 and YAP6 are within noise of wild type (0.973, 0.995),
  and FKH1 is at wild type (1.009).
- In this set the Costanzo 26 C and 30 C columns are identical for every deletion and DAmP
  strain; only the two ts alleles (MED4 `med4-6`, RGR1 `rgr1-100`) differ between the two
  temperatures.
- The three Kuzmin array values for a shared strain differ slightly from the Costanzo value
  and from each other (RFX1 `dma3249`: 0.9732 Costanzo, 0.962 Kuzmin 2018, 0.923 Kuzmin 2020
  S1, 0.9732 Kuzmin 2020 S3). Each screen normalizes its own arrays, so the rows are kept
  separate rather than averaged.

## 2026.09.18 - Wired into the document as Supplementary Note 5

The compact table is a second output, `results/tf-single-mutant-fitness-compact.tex`, one row per gene, naming an allele class only where the classes disagree. Two LaTeX lessons are baked into how it is written:

- **A file of bare table rows cannot be `\input` from inside a `tabular`.** LaTeX reports `Misplaced \noalign` at the `\bottomrule` that follows, whatever the path, the line endings or the trailing comment. The file therefore carries the whole `\begin{tabular}...\end{tabular}`, and the document inputs it at the top level of the float.
- **Hyphens, not underscores, in that one file name,** and the document's Makefile copies it into `notes-tex/008-xue-ffa-epistasis/tables/` (a `tables/%.tex` rule) rather than the tex reaching up through `../..`.

The note reports three things: MED4, RGR1 and TFC7 have inviable nulls in SGD and no deletion strain in any screen, so the screens carry ts or DAmP alleles; GCN5, the one factor whose deletion raises titer here, is absent from all five tables; and the seven non-essential factors run from 0.73 (SPT3) to 1.01 (FKH1).
