## 2026.10.15 - Attribution of the 4,233 dangling `PerturbationMemberOf` rows of the job 4901 partial

Lane A's CSV endpoint gate counted 4,233 `PerturbationMemberOf` rows naming no node (2,302 `:START_ID`, 1,931 `:END_ID`) of 47,251,386 in `/db/database/biocypher-out/2026-10-14_03-53-33`, where the audit had estimated 12 rows for the Carruthers gene-addition gap. `experiments/database/scripts/attribute_dangling_perturbation_rows.py` reads the same directory (read-only, 593 s) and attributes every row to a dataset through the `GenotypeMemberOf -> ExperimentMemberOf` ladder, then looks each missing id up in every other node file but `Experiment`. Output: `experiments/database/results/dangling_perturbation_rows_4901.json` (tracked).

**The 4,233 are reproduced exactly and contain zero rows of the Carruthers or Mutalik lane defect.** By dataset, counting an id as missing only when it is in NO node file (the gate's rule):

| dataset | side | rows | distinct ids | adapter's pass (log, UTC) | file the node row belongs to (mtime, CDT) |
|---|---|---|---|---|---|
| EnvChemgenYoshikawa2009 | START | 2,116 | 2,116 perturbations | nodes 19:29 to 19:31 | `Perturbation-part000.csv`, 14:31 |
| CrispriScreenRousset2018 | START and END | 174 both, 12 END | 174 perturbations, 186 genotypes | nodes 21:02 to 21:04 | `BacterialPerturbation` 16:04, `Genotype` 16:04 |
| RnaseqGuzman2018 | START | 12 | 12 called variants | nodes 20:01 | `BacterialSequenceVariantPerturbation`, 0 bytes, created 15:01 |
| CrispriSegregantHale2024 | END | 1,745 | 1,745 perturbed segregant genotypes | nodes 08:19 to 08:36 | `PerturbedSegregantGenotype`, 03:36 |

START 2,116 + 174 + 12 = 2,302 and END 1,745 + 186 = 1,931, the gate's two numbers. The four Carruthers adapters and the Mutalik compound never ran: they are in the 46-adapter tail after Shiver 2016, where the generation died (`4901_generate_after_timeout.log` line 11088, the `PhysicalExposurePerturbation` projection, 21:06 UTC = 16:06 CDT).

**Cause: the unflushed write buffers of the crashed generation, a partial-run artifact.** `torchcell.fast_csv.FastCsvSink._file` opens every `<Label>-part000.csv` with `buffering=1 << 20` and the handles are flushed in `finish()`, which the TypeError never reached, so the last 1 MiB of every label file is missing. Every dangling id above belongs to the LAST adapter that wrote that label's file: Yoshikawa 2009 is the last yeast dataset before the bacterial tail, so the `Perturbation` file's lost tail is its node rows (2,116 rows at 308 bytes per row, 652 KB, under 1 MiB); Rousset 2018 is the last adapter but Schastnaya 2021 before the crash, so the lost tails of `BacterialPerturbation` (174 rows, 430 bytes each) and `Genotype` (186 rows, 231 bytes each) are its rows, while its `PerturbationMemberOf` rows survived because that file's tail is Schastnaya's; Guzman 2018 is the only adapter that wrote the variant class, its 12 rows never filled the buffer and the file stayed empty; Hale 2024's `PerturbedSegregantGenotype` tail is 1,745 rows at 320 bytes, 558 KB. The files with 0 bytes (`SegregantGenotype`, `PhagePerturbation`, `Dataset`, `Genome`, `Temperature`, `FluxPhenotype`, `ProductTiterPhenotype`, ...) are the labels whose total output never reached 1 MiB. A complete build calls `finish()` and loses nothing, which is why the number is 0 and not 4,233 by construction; the next partial will dangle the same way, and the gate should say so rather than count it as a lane defect.

**A real defect the gate does not see: 121,237 rows whose genotype end exists only as an `InternedConstant` node.** The attribution's own rule (the end must be a genotype node) finds 125,239 dangling rows, not 4,233: Hale 2024 has 121,140 more END rows, the four Brunk 2016 stores 19 each (2 genotypes), Choe 2019 growth 21 (1 genotype), whose genotype id is in no genotype file but IS the id of an `InternedConstant` node. `FastCsvSink.seen_nodes` deduplicates node ids globally across labels (fast_csv.py 296, 349 to 358; the Deduplicator contract BioCypher inherits, since neo4j-admin import ids are global), and `interned_constant.constant_id` is sha256 of `json.dumps(value)`, the same bytes a genotype node hashes for its id. When a record interns its whole genotype (a bacterial `Genotype` over 8192 bytes; a perturbed segregant genotype), the `InternedConstant` row written by `_experiment_node` and the genotype row written by the genotype method carry one id, and whichever the sink sees second is dropped. The same collision leaves 135 of Hale's 170 segregant backgrounds under `InternedConstant` only (`SegregantBackgroundOf` start ids: 135 `InternedConstant`, 35 nowhere, the 35 being the lost tail), so every `GenotypeMemberOf`, `PerturbationMemberOf` and `SegregantBackgroundOf` edge of those records points at an `InternedConstant` node, and a served `MATCH (g:Genotype)` does not reach them. This reproduces on a complete build. It is not lane H's: the fix is in the writer or the interning (an interned constant id must not equal a node id, for example `constant_id = sha256("interned:" + payload)`, with the experiment blob's `$ref` and `neo4j_query_raw` reading the same id), and the CSV endpoint gate must check the label of a found endpoint against the edge's declared sources and targets, or it keeps reporting these as resolved. Filed for lane M in the PR body; the KG 4.0 build should not start before it is decided.

What a rerun of the gate on the unified lane will show, measured on the adapter unit tests and not a build: every genotype leaf of every mapped loader is served by `perturbation (chunked)` (177 of 177 in `test_loader_lane_exhaustiveness.py`, the three xfails gone), and `test_dev_store_emits_a_closed_declared_graph` runs the real adapter over the real dev stores (`--data`) and asserts no dangling edge, so the only rows a complete 4.0 generation can dangle are the interned-constant collisions above.
