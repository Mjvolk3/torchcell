# torchcell cron jobs (source of truth; entries are machine-specific paths).
#
# This file documents the durable cron entries torchcell relies on. It is NOT a
# complete install list for this machine -- other projects (Swanki, dotfiles)
# own their own entries in the live crontab. Add the block below by hand:
#
#   crontab -l | { cat; cat scripts/crontab.txt; } | crontab -
#
# ...or paste the merge-queue line into `crontab -e`. Verify with `crontab -l`.
#
# Status recording (`make jobs`): every job except the merge-queue drainer runs through
# `bash scripts/cron_run.sh <job-name> -- <command...>`, which appends the command's
# output to /tmp/torchcell-<job-name>.log and records start, end and exit code under
# ~/.local/state/torchcell/cron/, so `make jobs` can say whether the last run succeeded.
# The drainer runs every 2 min and already touches a heartbeat that `make jobs` reads
# (merge_queue.py loop-status), so it stays unwrapped.
#
# The job registry is CRON_JOBS in scripts/jobs.py (name, schedule, command):
# tests/scripts/test_jobs.py fails when a line here and the registry disagree, in
# either direction. To add a job, add a CronJob there and its wrapped line here.
# (A weekly `deps-weekly` dependency-update job, Sunday, is registered by its own PR.)

# merge-queue drainer: sweep free notes to main + land queued worktree branches
# (deterministic, no model; also triggered on-demand by /enqueue-merge).
# Self-flocks so it never races an on-demand drain. `bash -lc` sources the login
# shell so conda/PATH and (optionally) SLACK_CLAUDE_WEBHOOK are present.
*/2 * * * * bash -lc 'cd /home/michaelvolk/Documents/projects/torchcell && /home/michaelvolk/miniconda3/envs/torchcell/bin/python scripts/drain_merge_queue.py >> /tmp/torchcell-drain-merge-queue.log 2>&1'

# literature sync: nightly mirror + MinerU OCR of new papers in the Zotero group
# `database` + `paper` + `microbe-perturb-seq` collections AND the personal
# collection trees `torchcell` + `thesis` (the flags below are the list; add a
# `--personal-root NAME` per tree to mirror). Diff vs $DATA_ROOT/torchcell-library;
# captures only the new keys, and a key present in more than one collection or
# library is captured once. The mirror is served read-through by the tc-lit
# endpoint, so captured papers appear there (keys, /search, /bib) with no restart.
# A root missing from Zotero is logged as an error and the run exits 1; the other
# roots still sync. Self-flocks against on-demand runs. Runs at 03:30 on the
# GPU host so MinerU has the GPUs to itself. `--limit 10` bounds a big-backlog
# night's GPU time (applied per collection); drop it once the backlog is drained.
# Writes one JSON report per collection under torchcell-library/_sync_reports/.
# Then, whatever lit_sync's exit code, scripts/lit_annotations.py pulls Zotero
# highlights, comments and notes into the mirror next to each paper.md (GPU-free).
30 3 * * * bash -lc 'cd /home/michaelvolk/Documents/projects/torchcell && bash scripts/cron_run.sh lit-sync -- /home/michaelvolk/miniconda3/envs/torchcell/bin/python scripts/lit_sync.py --limit 10 --personal-root torchcell --personal-root thesis; bash scripts/cron_run.sh lit-annotations -- /home/michaelvolk/miniconda3/envs/torchcell/bin/python scripts/lit_annotations.py'

# bibliography store: nightly headless Zotero Web API export of every repo-declared
# bibliography (group `paper` collection, one per notes-tex document, the whole
# torchcell union) into torchcell-library/_bib/ with a sha256 manifest, which tc-lit
# serves at /bib and /bib/<name>. Writes nothing git-tracked, so cron cannot dirty a
# checkout; consumers pull a pinned copy with `make bib-pull`. Runs after lit_sync so
# a paper captured that night is citable the same morning.
45 3 * * * bash -lc 'cd /home/michaelvolk/Documents/projects/torchcell && bash scripts/cron_run.sh lit-bib-store -- /home/michaelvolk/miniconda3/envs/torchcell/bin/python scripts/lit_bib_store.py'

# deprecation-graveyard retention sweep: remove graveyard entries that have STAYED past the
# retention window (14 days), keeping recent ones. The 14-day RETENTION is enforced by the
# script's age gate (age read from each entry's moved-in timestamp), so this runs DAILY and
# purges each item promptly the day it crosses 14 days. (For a literal "every 14 days"
# cadence use `0 4 */14 * *` instead -- but then an item can linger up to ~a month before a
# run catches it; daily + age-gate is the precise way to get "removed after staying 14 days".)
# Sweeps both /tmp and the /scratch sibling graveyard; never touches non-deprecate entries.
0 4 * * * bash -lc 'cd /home/michaelvolk/Documents/projects/torchcell && bash scripts/cron_run.sh purge-deprecated -- bash scripts/purge_deprecated.sh'

# mirror backup: weekly (Sunday 02:00) non-destructive rsync of the two provenance mirrors,
# $DATA_ROOT/torchcell-library (papers, OCR, SI, released data + manifests) and
# $DATA_ROOT/torchcell-raw (raw files each loader consumed for its first successful build),
# into the /bulk archive tier. No --delete: a file removed on /scratch stays archived.
# Seeded once by scripts/migrate_storage_tiers.sh (2026-08-23); this keeps it current, so a
# rebuild never depends on a live URL (upstream sources have vanished before).
0 2 * * 0 bash -lc 'cd /home/michaelvolk/Documents/projects/torchcell && bash scripts/cron_run.sh backup-mirrors -- bash scripts/backup_mirrors_to_bulk.sh'

# weekly dependency update: Sunday 05:00, install the newest versions env/requirements.txt
# allows (and the newest torch with a PyG torch_scatter wheel) into a fresh venv, run
# `pytest tests/torchcell`, and when it passes open a PR that raises the floors, moves
# the CI torch and rewrites env/tested/requirements.lock.txt; `--land` enqueues that PR
# once its checks pass. A red suite files one issue instead. Policy (held floors, caps):
# env/deps_policy.toml. The primary checkout can sit behind origin/main, so the line
# reads origin/main's scripts/deps_weekly_cron.sh, which runs the job in a fresh
# detached worktree under /scratch/tmp/torchcell-deps-weekly/ and removes it after.
# Report: `make deps-report`. See scripts/deps_weekly.py.
0 5 * * 0 bash -lc '( git -C /home/michaelvolk/Documents/projects/torchcell fetch -q origin && git -C /home/michaelvolk/Documents/projects/torchcell show origin/main:scripts/deps_weekly_cron.sh | bash -s -- /home/michaelvolk/Documents/projects/torchcell ) >> /tmp/torchcell-deps-weekly.log 2>&1'
