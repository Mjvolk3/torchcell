## How provenance is recorded

Every dataset page begins with where each source file came from, how it was
retrieved, and the hash of the bytes used. The same record is served with the dataset
(`provenance` in `GET /datasets`) and shown, folded, at the top of its panel on the
[leaderboard](../leaderboard.mdx). The rule is the project's: a stored file and its
sha256 are canonical, a URL is retrieval history, and a rebuild re-runs the recorded
retrieval and verifies the hash rather than trusting the live site.


A bundle is built by a committed script under `experiments/035-benchmark-bundles/`,
which writes the provenance block into the bundle and a full build record into that
experiment's `results/`.

## Split files

A **split file** is a CSV with the columns `record_id,split`. It assigns every record
of a dataset to one split, train, validation, or test, and every submission to that
dataset is scored on the same validation and test records. The split file and an empty predictions template are downloadable from the
dataset panel on the [leaderboard](../leaderboard.mdx), and from the API:

| File | Route | Columns |
| :-- | :-- | :-- |
| Split file | `GET /datasets/{slug}/splits.csv` | `record_id,split` |
| Predictions template | `GET /datasets/{slug}/template.csv` | `record_id,split,target,prediction`, with `prediction` empty |

Every dataset is also listed by the API, unranked or searched:

| Purpose | Route | Answer |
| :-- | :-- | :-- |
| Every dataset | `GET /datasets` | the public record of each dataset |
| Search | `GET /datasets/search?q=&organism=&task_group=&limit=20&offset=0` | `{mode, total, limit, offset, results: [{dataset, score}]}`, best first; an empty `q` lists every dataset by organism, task, split and title; `limit` is at most 100 |
| Task search | `GET /tasks/search?q=&organism=&key=&limit=20&offset=0` | `{mode, total, limit, offset, results: [{key, task_group, title, organism, n_boards, score, boards}]}`, one row per task, best first; `boards` lists at most 50 boards (`slug, split_name, title, n_train, n_val, n_test`) by split family, then seed; an empty `q` lists every task by organism and title; `key` keeps one task |
| Browse tree | `GET /datasets/facets` | board and task counts per organism and, within each, board counts per task group |

A dataset record names its `organism`, its `task_group` (the task its split boards
share) and its `split_name` when the bundle sets them. A **task** is the boards that
share a `task_group`, or one board without one (its `key` is then the board's slug);
the task search matches the task's title, organism, targets, loader class, citation
key and the part of the description its boards share, never a split name, so a query
answers each task once. `mode` is `lexical` (word and
word-start matches, titles, slugs and organisms weighted above descriptions) or
`hybrid` (the same, averaged with the cosine similarity of a small text-embedding
model); `GET /health` reports which one the service runs as `search`.

## Targets

A **target** is one predicted quantity. A dataset with one measured value per record
has one target. A dataset with several measured values per record, such as a set of
amino acid levels, has one target per value, and its scores are averaged over targets
as described under [Metrics](../metrics.mdx).
