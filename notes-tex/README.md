# `notes-tex/` — typeset long-form documents

The LaTeX counterpart to `notes/`. Dendron notes are the working layer; a document
here is the typeset deliverable that grows out of one — a design memo, a method
plan, a thesis chapter draft.

This is **not** `docs/` (Sphinx API documentation for the package) and **not**
`paper/` (the Nature Biotechnology manuscript, which syncs to Overleaf).

## Prose standard -- read before writing

**[[writing-style-guide]]** (`notes/writing-style-guide.md`) is the canonical prose
standard, and it applies here more than anywhere: these documents are the ones
colleagues actually read end to end, and they were where every rule in it was
learned. `make check` enforces the mechanical half -- American spelling, no
em-dashes -- and fails the build on a violation. The half it cannot check is the
one that matters most:

> **Trailing restatement.** A clause appended to a sentence that re-says what the
> sentence already said. *"Every molecule tagged inside that droplet shares a
> barcode **because the droplet wall keeps it that way**."* The droplet already
> did the work.

A gate that tried to detect this ran at about one true positive in ten and was
removed; see the note in `common/check_doc.py`. It is a manual read.

Also enforced by eye, not by the gate: do not narrate the document ("This document
asks..."), do not be self-referential about the group, and define every technical
term in the controlled vocabulary before it appears in prose or a figure label.

## Pairing is by name

```
notes/experiments.024-perturb-seq-costing.method-review-and-costing.md   <- dendron working notes
notes/experiments.024-perturb-seq-costing.tables.md
notes-tex/024-perturb-seq-costing/                            <- the typeset document
```

`notes-tex/<slug>/` pairs with the `notes/<slug>.*.md` hierarchy, and with the
Zotero group collection of the same name. That is the same name-based rule that
already pairs `experiments/013-.../scripts/foo.py` with
`notes/experiments.013-....scripts.foo.md` — not a new convention, an existing one
applied to a new file type.

Every `.tex` file opens with the three-line header the repo already uses for
Python, in `%%` comments:

```latex
%% notes-tex/024-perturb-seq-costing/main.tex
%% [[experiments.024-perturb-seq-costing.method-review-and-costing]]
%% https://github.com/Mjvolk3/torchcell/tree/main/notes-tex/024-perturb-seq-costing/main.tex
```

## Layout

```
notes-tex/
  common/
    tcdoc.sty         shared machinery: status chips, tcfig, geometry, provenance markers
    Makefile.common   tectonic build, Zotero bib export, draw.io export, the check gate
    check_doc.py      formatting / provenance / citation gate
  <slug>/
    main.tex          document root; %% NOTE: header links back to dendron
    sections/*.tex    one file per top-level section
    tables/*.tex      GENERATED by a script under experiments/ -- never hand-edited
    figures/*.pdf     generated; SVG sources live in notes/assets/images/ or drawio/
    references.bib    GENERATED by `make bib` from the Zotero group collection
    Makefile          sets DOC + ZOTERO_COLLECTION, includes ../common/Makefile.common
```

`tcdoc.sty` is symlinked into each document directory at build time (Tectonic does
not honor `TEXINPUTS`). The symlink is gitignored and any build recreates it, so a
fresh clone needs no setup.

## Build

```bash
cd notes-tex/<slug>
make              # main.pdf, draft view: status chips + provenance flags
make clean-view   # main-clean.pdf, for sharing outside the group
make check        # formatting / provenance / citation gate
make bib          # re-export references.bib from Zotero (needs Zotero + Better BibTeX running)
make figures      # re-export any draw.io sources the document references
```

## The status stoplight

Same notation as the manuscript and `CLAUDE.md`. Put `\secstatus{...}` **inside**
the heading braces:

```latex
\section{Theoretical Limits\secstatus{todo}}
```

- `todo` — red ✗, not done; coding agents may edit freely
- `tent` — amber ■, author-reviewed, keep stable; discuss before editing
- `final` — green ✓, ready

Because the chip sits inside the heading, it appears in `\tableofcontents` for
free. **The TOC is the status board** — there is no second hand-maintained list to
drift out of sync with the sections. `make check` prints the same summary to the
terminal and flags any heading missing a chip.

## Gotchas the gate will catch

- **Use `\file{path/to/thing.py}` for paths, not `\texttt{}`.** `\texttt` refuses to
  break at a slash, so a long repo path silently runs off the page — the exact
  overfull-hbox defect `make check` exists to flag. `\texttt{}` is still right for
  short identifiers.
- **Wide tables** need fixed-width `p{}` columns for their free-text fields. Set
  this in the generating script, not the emitted `.tex`.
- **Figure captions** are non-moving (`\caption[]{...}`) so fragile commands like
  `\file` work inside them.

## Provenance

Two layers, and both are enforced by `make check`:

1. **`%% SOURCE:` comments** above any generated content, naming the script that
   produced it — or saying explicitly that it is hand-authored. A file containing
   a table but no `%% SOURCE:` line is a warning.
2. **Visible flags** for anything not backed by the `torchcell-library` mirror:
   `\external{why}` for a fact from outside our holdings, `\secondhand{source}`
   for a value taken from a review's table rather than the primary paper. These
   render even in the clean/share view — an unverified number must never lose its
   flag just because the document left the group.

Citations are gated too: `make check` fails on any `\cite` key absent from
`references.bib`, which is the mechanical form of *add the paper to the library
before citing it*.

## Bibliography: two tiers, deliberately different

| Target | Source | Why |
|---|---|---|
| `paper/nature-biotech/references.bib` | **group `paper` collection only** | Publication guarantee — every work cited in the manuscript lives in a library the whole group holds, so citations stay recoverable after publication. Built by that directory's own `zotero_export_bib.py`; nothing in `notes-tex/` touches it. |
| `notes-tex/<slug>/references.bib` | **union of the group and personal collections of the same name** | Technical notes cite far more widely than the paper, and much of that reading lands in the personal library first. Requiring a promote-to-group round trip before anything can be cited would just stop notes being written. |

The union is built by `common/build_bib.py` (`make bib`). Group entries win on a
clean overlap, since that copy is the curated one.

### Citekey collisions

The union is where two libraries can disagree, so `make bibcheck` reports two
distinct failures and names the keys so they can be found in Zotero:

- **Key conflict** — one citekey, two *different* works. **Fatal**: whichever copy
  wins, some citation now points at the wrong paper. `make bib` refuses to write.
- **Duplicate work** — one work (same DOI or title) under *two* citekeys. Not
  fatal, but it splits one reference into two numbered entries in the PDF.

Both print the citekey, which library each side came from, both titles, and the
fields that differ. `make bibcheck` writes nothing and exits non-zero on a
conflict, so it is the CI-able form.

> **Not yet in CI.** `bibcheck` needs a running Zotero with Better BibTeX on
> `localhost:23119`, which a GitHub runner does not have. Wiring it up means
> either committing a bib snapshot and checking *that* (no Zotero needed), or
> running it as a pre-commit hook on the machine that has Zotero. Until then it is
> run by hand.
